The problem, in one listing

Interaction gated information is data that exists on a page but is only reachable through interaction. The agent's first observation gives no signal that anything is missing.

Some prices only appear after you click. Nothing on the page warns you they exist, so an AI reading that page has no idea it is missing anything.

GLENMOOR STILL SPRING WATER, CELLAR DIRECT
12 x 550ml$1.50/L$9.89
24 x 350ml$1.42/L$11.90
6 x 1.25L$1.40/L$10.50
2 x 9.5L$1.31/L$24.90

The shaded row is the only price in the rendered page on load, the cheapest variant rather than the best value. The amber row is reachable only after selecting that variant.

The grey row is the only price you see when the page opens. The amber row, which is actually the best value per litre, appears only after you click.

A live AI shopping assistant, asked for the cheapest 9.5L carton, returned a ranked comparison naming one seller as 27 per cent cheaper, with a supporting cost per litre figure. It was wrong. That seller was more expensive for the size requested. No merchant did anything deceptive and no attacker was involved.

A real AI shopping assistant was asked which seller had the cheapest 9.5 litre carton. It confidently said one seller was 27 per cent cheaper and even showed the maths. It was wrong. That seller was the dearer one for that size. Nobody cheated. The AI just did not look hard enough.

That is the gap this project addresses. Prompt injection defences assume an adversary. Here there is none, only a retrieval policy that stops too early and a reporting layer that never signals doubt.

This matters because most AI safety research looks for attackers. This failure has no attacker at all. The AI simply stopped looking too soon, and never said that it was unsure.

Four forms of gating, and how deep each one is

Price by variant is the form built and measured so far. It is also the shallowest, because one click reveals the missing figure. The supervisor's suggestion to add discounts and vouchers turns out to matter more than realism, because it reaches a depth the current method's guarantee does not survive.

So far the project covers one kind of hiding: the price changes when you pick a size. That is the easy kind, because one click reveals it. Adding discounts and vouchers, as the supervisor suggested, is not only about realism. It reaches a kind of hiding that breaks the shortcut the method depends on.

FormWhat is hiddenInteraction neededStatus
Price by variantThe price of the option you wantOne click, reversibleBUILT AND MEASURED
Stock by variantWhether the option can be bought at allOne click, reversibleBUILT AND MEASURED
Price by quantityA tier discount that only applies above a thresholdSet a quantity, still on the pageDESIGNED, NOT BUILT
Price by cart stateWhether a voucher applies, and what the total actually becomesAdd to cart, enter a code, and the state persists across pagesDESIGNED, NOT BUILT

The fourth row is different in kind, not degree. A variant click is reversible and local: select another size and the page returns. A cart is global and persistent, so retrieving the answer changes the state that later retrievals happen in, and an exploratory add-to-cart has to be undone rather than simply navigated away from. Any policy that treats retrieval as free observation is wrong here.

The last row is a different kind of problem, not just a harder one. Clicking a size is undoable and affects nothing else. Putting something in a basket changes the state of everything after it, and has to be actively undone. So checking a price is no longer a harmless look.

from price is a valid lower bound   →   skip the listing from price minus an unknown voucher   →   the bound is unsound

That is the real consequence, and it is a limitation rather than an inconvenience. The exact method for comparison questions is branch and bound, which prunes a listing when its advertised "from" price already exceeds the best total found. That is only sound because no variant can cost less than the "from" price. A voucher makes the true minimum payable lower than the advertised figure, so the bound no longer holds and pruning could skip the actual winner. The measured pruning result is therefore stated as holding in the absence of voucher pricing, which is now an explicit scope boundary rather than an unexamined assumption.

Here is why it matters. The method saves time by skipping shops whose cheapest advertised price is already too expensive to win. That is safe only if nothing can be cheaper than advertised. A voucher makes things cheaper than advertised, so the shortcut could skip the actual winner. The result stands, but only for shops without vouchers, and that limit is now written down rather than assumed.

Where this sits in the literature

The project is not the first to want an agent that knows when to stop. Five established lines of work address something adjacent, and each rests on an assumption this failure violates. The distinction in one line: abstention research asks whether a model knows that it does not know. This asks whether an agent knows that it did not look.

Plenty of research already tries to make AI admit when it is unsure. Five separate fields work on it, and each one assumes something that is not true here. The short version: they ask whether the AI knows it is ignorant. This asks whether the AI knows it never checked.

How this project got here

The registered title names injection defences because that is where the work started. The direct predecessor is StakeBench, arXiv 2606.13385, which runs indirect prompt injection against web agents in OneStopMarket, the WebArena shopping site this project also uses, with deployable agents rather than research prototypes, and reports attack success between 41.67 and 68.59 per cent. Behind it sit InjecAgent, arXiv 2403.02691, which established the tool-integrated agent injection benchmark, and WASP, arXiv 2504.18575, which did the same for web agents.

The project began as a security project, which is why the registered title mentions attacks. The closest earlier work runs attacks against shopping agents in the very same test shop this project uses, and finds they succeed between 41 and 69 per cent of the time. Two other papers built the benchmarks that made that possible.

The pivot came from a single observation about that literature. StakeBench's most interesting finding is that a user-targeted attack often succeeds while the delegated task still completes, so nothing looks wrong from the outside. That is a statement about detectability rather than about adversaries, and the same undetectability arises with no attacker at all: on a gated listing the agent reports a price, the task completes, and the answer is wrong. Removing the adversary leaves the failure and the invisibility intact, which is what suggested the adversary was never the load-bearing part.

The change of direction came from one observation. That paper's most striking finding is that a successful attack often looks like a completed job, so nobody notices. But the same invisibility happens with no attacker: the AI reports a price, the task looks done, the answer is wrong. Take the attacker away and the dangerous part is still there, which suggested the attacker was never the important bit.

There is also a defensive argument. Injection defences work by filtering or isolating what enters the agent's context, and the field's own results show those defences are fragile, with adaptive attacks breaking existing ones, arXiv 2503.00061. Even a perfect filter cannot help here, because there is nothing harmful in the context to remove. The defect is an absence, and absences do not arrive to be filtered.

There is a second reason. Defences against attacks work by removing bad content before the AI reads it, and even those are unreliable. But a perfect filter would not help here, because nothing bad was read. What went wrong is what was never read at all, and you cannot filter out something that is missing.

Five works, and where each one stops

Fewer papers, read for what they establish and where they run out, rather than a survey. Each of these constrains the design of what was built.

Five pieces of existing research, read properly rather than listed. Each one changed a decision in this project.

1. Models mostly know what they know Kadavath et al. 2022

Trained to predict P(IK), the probability that it knows an answer, a large model does well. The detail that matters here is that P(IK) "increase[s] appropriately in the presence of relevant source materials in the context". Self-knowledge is conditioned on the context.

This paper shows AI can judge whether it knows something. Importantly, it gets more confident when the right information is actually in front of it, which is the sensible behaviour.

The measured result here looks like a contradiction and is not. The confidence arm found AUROC 0.528 and an agent rating itself 95 while writing "I verified all 4 sellers" where there are fifteen. But on a gated listing the relevant source material is in the context: the price it read is real and correctly parsed. Conditioned on the four listings it opened, it does know the answer, and high confidence is the right output. The failure sits upstream of the quantity Kadavath measures.

Our result looks like it disagrees, and it does not. The AI read a real price correctly. Given the four shops it looked at, it genuinely did know the answer. The problem happened earlier, when it decided four shops was enough.

The structural difference is that their model is given a context, and an agent chooses its own by acting. Self-knowledge conditioned on a context cannot detect that the context was badly chosen, because the choosing happened earlier and leaves no trace inside the result. So the check has to read something outside the context, namely the record of what the agent did. Any signal computed from the context alone inherits the same blindness.

The difference is that in their experiments the AI is handed the information. Here it goes and gets its own. Judging how sure you are about what is in front of you cannot tell you that you fetched the wrong things. That is why the check reads the record of what the AI did, not what it ended up holding.

2. Models cannot self-correct reasoning Huang et al. 2023

Correcting an answer "based solely on its inherent capabilities, without the crutch of external feedback" fails on reasoning tasks, and performance sometimes degrades. Later work adds a self-correction blind spot: a model repairs an error shown to it but not the identical error in its own output.

Asking an AI to check its own work does not work, and sometimes makes things worse. It can fix a mistake someone points out, but not the same mistake when it made it itself.

This rules out the cheapest fix, which would have been one extra model call and no browser actions. It also explains why: a second pass over the same context re-derives the same answer, because nothing in that context is wrong. Both arms built here therefore supply the fault from outside, and the retry now hands back the agent's own sentence set against a fact. That is a deliberate use of the blind spot rather than a workaround, since the claim is the agent's and so undeniable, but arrives externally and so is open to correction.

This ruled out the cheap fix of asking the AI to double-check itself. So the correction is always supplied from outside. The retry now quotes the AI's own sentence back to it, which is the one thing it cannot argue with, while still arriving from outside where it can act on it.

3. Self-RAG Asai et al. 2023

The closest method ancestor. A model is trained to emit reflection tokens controlling retrieval and checking output, among them Retrieve, which decides whether more evidence is needed, and ISSUP, which judges whether the output is supported by the evidence. That second question is close to the one asked here.

The nearest existing method. It trains an AI to decide when to go and look things up, and to check whether its answer is actually supported by what it found. That second check is close to what this project does.

Self-RAGThis project
What supports the claimRetrieved passagesThe interaction trace, what the agent did
How the check worksLearned tokens, needing a critic and a fine-tuned generatorRules over recorded text. No training, works through a black-box API, costs nothing
Who chooses the evidenceThe retriever, given a queryThe agent, by acting. Choosing too little is the failure

The third row is the substantive one. ISSUP asks whether the text follows from the passages in hand, so an answer can pass it and still be wrong because those were the wrong passages. In a corpus setting that is the retriever's problem. In an agent setting there is no retriever to blame: the agent decided by clicking or not clicking, so the check has to reach the decision rather than the text.

The last row is what matters. Their check asks whether the answer follows from the documents it has. It can pass while being wrong, because the wrong documents were fetched. In a search engine that is the search engine's fault. Here the AI chose what to look at, so the check has to reach that choice.

Runs indirect prompt injection against web agents in OneStopMarket, the same WebArena shopping site used here, with deployable agents, reporting attack success between 41.67 and 68.59 per cent. 5. When web agents finish but still fail 2026

Trace-level analysis over a parallel web-exploration benchmark finds three persistent failure modes, one being premature termination on partial answers. That is this project's failure, found independently, in a different environment, with different agents. Corroboration rather than competition, and evidence the failure is not an artefact of WebArena or openJiuwen.

A separate paper studying web agents finds the same thing: they stop early and answer from partial evidence. Different setup, different AI models, same failure. That means this is real rather than a quirk of our test shop.

It is diagnostic, and concludes that the remaining gap "requires evidence-grounded coverage and synthesis diagnostics". That sentence is a specification, and what was built here is an implementation of it: a coverage and evidence check running as a policy rather than an analysis, applied before the answer is emitted, validated on runs made after the rules were frozen.

It diagnoses without fixing, and ends by saying what is needed is a way to check coverage and evidence. That is what this project built and measured.

Adjacent, considered, not central

Calibration and verbalised confidence, unanswerable question answering and context sufficiency, attribution and citation faithfulness. Each is one step removed for the same structural reason as Kadavath: they evaluate a model against a context or an evidence set that someone else fixed. The move here is to evaluate an agent against the evidence set it chose for itself.

Several other fields are close but all share one assumption: someone hands the AI the information and asks whether it judged it well. This project asks whether the AI went and got the right information in the first place.

What this project claims that is not already claimed

Three things, stated narrowly enough to defend.

Three claims, kept small enough to actually stand up.

  • A failure class defined by absence rather than error. Interaction-gated information produces a context in which every observation is correct and the answer is still wrong. That is not covered by uncertainty over a given context, nor by faithfulness to a given evidence set, because the defect is in what was never observed.A kind of failure where nothing the AI saw was wrong. Everything it read was accurate. The answer is still wrong, because of what it never went to look at. Existing methods check what is there, so they cannot see this.
  • A sufficiency check grounded in the action trace, not in model confidence. The rules compare what the answer asserts against what the run observed, using arithmetic and coverage. They need no logits, no second model call and no fine-tuning, so they cost nothing and work through a black-box API. On two batches the frozen rules never saw it withdraws 6 of 10 wrong answers and withholds 1 of 14 correct ones. Over all 107 unmodified runs on the two current markets it withdraws 16 of 22 wrong answers and withholds 3 of 85 correct ones: two correct yes-or-no answers that mention a surcharge the rule reads as a price, a false positive reported as one, and one answer that was right after opening 4 of 15 listings.A check that reads the record of what the AI did, not how sure it sounds. It needs no access to the model's internals and no extra AI call, so it is free. On runs it was never tuned on, it withdraws 6 of 10 wrong answers and holds back 1 right one. Across all 107 runs it withdraws 16 of the 22 wrong answers and holds back 3 right ones: two where the check mistook an extra charge for a price, and one that was right by luck after checking only four of fifteen shops.
  • Soundness reported separately from correctness. On one task the agent opens exactly four of fifteen listings in every run, so its single correct answer rests on the same evidence as its six wrong ones. An accuracy-only evaluation cannot distinguish those, and this project reports both.Measuring whether an answer was earned, not only whether it was right. On one question the AI checks exactly four of fifteen shops every single time. The one time it was right, it was right by luck on the same evidence that made it wrong six times. Marks out of ten cannot see that.

    Finding 1. It never admits uncertainty

    Zero abstentions in sixty runs, and none in the 107 unmodified runs across both current markets. The scorer tests a wide hedge vocabulary, including unable to, could not determine, insufficient and unclear, and none ever fired. Every failure is a confident assertion, so no downstream consumer can distinguish a guess from a verified answer.

    Finding 3. Failures are delta misreadings, not inventions

    "The price of the 2 x 9.5L pack is $15.01"   truth $24.90, 1 action "The price of the 2 x 9.5L pack is $11.60"   truth $22.50, 1 action, 8 Sep run only

    Corrected 9 September after re-reading the traces. This was originally reported as fabrication. 14 September: in the clean re-run this happened once in 55 gated runs, the $15.01 case. The $11.60 case appeared only in the 8 September run.

    Neither figure appears in the page source, which is what first suggested invention. The traces show something more specific. Magento labels each variant option with a price delta, and both runs observed exactly that: 2 x 9.5L +$15.01. Then $9.89 + $15.01 = $24.90, and $10.90 + $11.60 = $22.50. Both numbers are correct as surcharges. The agent retrieved the right token and misread its semantics, reporting a relative value as an absolute one. The label is computed in the browser from the page's own configuration block rather than written into the HTML, which is why a source check found nothing while the agent saw it plainly.

    At first this looked like the AI making numbers up, because neither figure is anywhere in the page's code. Reading what the AI actually saw shows something different. The size dropdown does not list prices, it lists surcharges: the option reads "2 x 9.5L +$15.01", meaning fifteen dollars more than the price already on screen. Add them and you get $24.90, the right answer. The AI read the surcharge and reported it as the price. It found the right number and misunderstood what it meant.

    The other runs on the same task composed both values correctly and said so, which identifies composition rather than retrieval as the discriminating step. This is a sharper result than the original claim: interaction-gated prices are frequently expressed relative to the visible price, so the gated token only means anything combined with the headline the agent already had. The resulting error looks like a price, sits in a plausible range, and appears nowhere on the page, which makes it harder to catch than either a stale headline or an invention.

    One run out of the three did the sum properly and showed its working, which proves the AI can do it. The lesson is that hidden prices are often written as "add this much" rather than as a total, so an agent has to combine two numbers rather than read one.

    It also changes what the retrieval policy has to do. A coverage check, asking whether the required field was observed, passes both of these failures. What catches them is a consistency check: an absolute price reported after a delta label was seen must equal base plus delta. That is arithmetic requiring no further page fetch.

    This changes the fix. Checking "did the AI look?" would not catch these, because it did look. Checking "does the number it reported add up?" would.

    Two arms, because they cost different amounts

    The check is a judgement. A policy is what the system does with it, and there are two separable options. Gate replaces an unverified answer with an abstention naming what could not be confirmed, and issues no browser action, so it adds no model cost. Retry re-asks the task with the reason attached, and pays a full second run.

    Two versions. The cautious one refuses to answer and says why, which is free because it does no extra looking. The expensive one goes back and tries again, told what it got wrong, and that costs another whole run.

    The gate is free, so it runs on runs already recorded

    Because the gate never touches the browser, replaying it over a finished run gives exactly the verdict it would have given live. Over the 107 unmodified runs on the two current markets it withdraws 16 of 22 wrong answers and withholds 3 of 85 correct ones: two correct yes-or-no answers that mention a surcharge the rule misreads as a price, and one answer that was right after opening 4 of 15 listings. The earlier method, rescoring each answer and dropping it if today's scorer disagreed, let one superseded run through whenever its answer happened to be wrong under both answer keys.

    Because the cautious version does no extra looking, it can be applied to runs that already happened and the answer is exactly what it would have been at the time.
