In short A shopping agent answers from the page it can see. When the price, size or stock a question needs only appears after a click, it often answers anyway, and wrongly, without saying it is unsure. The tests of the last two weeks say where that failure comes from and what it costs to avoid. The block built this week sits in front of the agent. It reads the question and the first page, hands the agent a plan, asks the user back when the question is ambiguous, and checks the answer against the page afterwards. In its pilot it got both questions right, and on the cheapest question it opened listings instead of 15 for , where opening everything costs about $0.59. The second version, built today, covers every question shape the shopping benchmarks contain, with a model doing the parsing and rules doing the rest.

2. Building the block

What it does

PlanIt reads the question and the first results page, then gives the agent the number of listings, the listings in order of advertised price with their URLs, and a strategy with a stop rule: open these, in this order, and stop when no unopened listing can change the answer.
Ask, push back, or pass throughWhen the question has two readings it asks which one is meant. When the question needs something the shop does not show, it says so and nothing runs. When the question is not about shopping at all, it hands it to the agent unchanged and counts that this happened.
CheckAfter the agent answers, it decides from the page alone whether the answer is supported by what was opened, and refuses it if not. It never reads an answer key.
Version 1 and version 2Version 1 ran the pilot above with four fixed strategies. Version 2, built today after the research below, turns any question into a logical form, lets a model do that parsing, checks the form against five properties, and builds the plan from seven primitives. On the six clothing questions it produces exactly the same text as version 1, so the pilot result still stands.

Should the block be an agent?Partly. A model parses the question, because that takes judgement, and on the project's 37 questions it agreed with the rules on the fields that decide the plan times out of . Rules do everything after that, because their stop rules can be proved, their checks can refuse an answer the model is sure about, and the same input gives the same text every time. A fully agentic block would be Test 4 with extra steps, at times the cost, and Test 4 is what the block has to improve on.

How to read the four numbersThe first two are about judgement and they are high. The second two are about vocabulary: the prompt never told the model to put the listing's URL among the conditions, and the model wrote "listing" where the rules write "results". Why this matters, and what it is not

It does not replace the agent

The block works with whichever agent is used

It sits in front of the agent and hands it text, and it never browses on its own. Test 3 shows that the two errors it targets besides coverage, the ambiguous verb and the price read too early, also appear in a second agent built from scratch. Putting the block in front of that agent is next week's check.

It answers questions rather than buying

The step before the purchase button

Every purchase an agent makes starts with a retrieval question: which offer, at what price, in which size, is it in stock. A wrong answer there turns into a wrong purchase one click later. The live assistant observed in August named one seller 27% cheaper for a carton it was actually dearer for, with no sign of doubt. The block makes that answer correct at a known cost, and says when it cannot. Buying, discounts, coupons and delivery are out of scope and stated as limits. Reviews are in scope and come next.
