In one paragraph

A shopping agent answers from the page it can see. When the price, size or stock a question needs only appears after a click, the agent often answers anyway, confidently and wrongly. Last week's two tests showed the shipped agent opens what the answer needs in of 15 runs, and that one default in its card probe is the cause ( of 15 with it off). This week added a second agent, an "open everything" ceiling, and the first run of a block that sits before the agent: it reads the question and the first page, hands the agent a plan, asks the user back when the question is ambiguous, and checks the answer from the page. The block's pilot got both questions right, opening listings instead of 15 on the cheapest question for against about $0.59. Version 2, built today, generalises the block to every question shape the shopping benchmarks contain, with a model parsing the question and rules doing everything after.

2. Building the block

What it is

A step that runs before the shopping agent. It reads the user's question and the first results page, and does one of three things: hands the agent a plan (how many listings there are, which to open in what order, when to stop, what counts as evidence), asks the user back when the question is ambiguous or names something the shop does not show, or passes a question that is not about shopping straight through and counts it. After the agent answers, the block decides from the page alone whether the answer is supported, and refuses it if not. Version 1 ran the pilot above with four fixed strategies. Version 2, built today after the research below, handles every question shape in the shopping benchmarks and lets a model do the parsing.

Why this matters, and what it is not

Agent agnostic. The block does not replace a browser agent and is not one. It sits in front of whichever agent is used and hands it text. Test 3 is the evidence that the two errors it targets besides coverage, the ambiguous verb and the price read too early, appear in a second agent built from scratch; the block in front of that agent is next week's check.

Answering, not buying. Every purchase an agent makes is a retrieval question first: which offer, at what price, in which size, in stock. A wrong answer there becomes a wrong purchase one click later, and the live assistant observed in August named one seller 27% cheaper for a carton it was dearer for, with no sign of doubt. The block makes that answer correct at a known cost, and says when it cannot. Buying, discounts, coupons and delivery are out of scope and stated as limits. Reviews are in scope and come next: they gate by depth, not by a click, and the block already has the primitive for them.
