2. Solved: the shop no longer gives prices away

1

Bug: Magento, the shop software, sends the browser every size's price when the page loads, and the menu then writes each one as a surcharge.

So an agent could read $16.14 from the page, add $32.50 from the label, and report $48.64 without ever selecting the size. Which is exactly what it did: across 290 stored answers, 48 showed the agent adding a surcharge instead of clicking.

2

I built a replacement page template that flattens the price table the shop hands the browser, so every size reports the same starting price and no label can show a difference. The real prices travel hidden, and are written into the price box only for the size actually chosen.

3. Solved: why the agent only saw 4 listings of 15

This is the question you asked last week, and the answer took three attempts to figure out.

1

The agent does read the page properly. It is not working from screenshots. Across 361 recorded runs it read the page structure 3,645 times, as 1,662 page snapshots, 1,561 searches of the page and 422 card summaries, and took only 278 screenshots as a fallback, roughly thirteen to one.

2

The page is complete too. All fifteen products are in it. I measured them on one page load.

One search page, measured
MeasureValue
Product listings present in the page15
Listings whose top edge is inside the browser window4
Where the first off screen listing begins1008 pixels down
3

So where do the other eleven go? The agent has a tool that summarises the products on a page. That tool has a setting, on by default, that throws away anything below the bottom of the window. It finds all fifteen, then discards eleven.

And the reply it sends back never says anything was dropped (means it's not aware). It reports four and stops.

4

How I fixed it: I wrote a small patch in our own repository that flips that one setting and changes nothing else: same instructions, same tools, same model, same budget, same shop. The agent is never told about the change.

The result is in section 5.

What I thought happened: openJiuwen's public talk says the agent reads the page by default and uses screenshots only when the page is unclear. That claim is true. I thought otherwise at one point and was wrong. The problem is not that they avoid reading the page. It is that their summarising tool quietly drops most of it and does not say so.
