2. The problem found
Interaction-gated information is data that exists on a page but is only reachable through interaction. The agent's first observation gives no signal about what is missing.
  



Observation
	What I found
	The listing title advertises four pack sizes
	24 x 350ml, 12 x 550ml, 6 x 1.25L, 2 x 9.5L
	Only one price is in the rendered DOM at a time
	Confirmed by DevTools search. Selecting a different size replaces it
	The headline price is the cheapest variant
	$9.89, which is the 12 x 550ml, not the 2 x 9.5L
	The 2 x 9.5L price only appears after clicking
	

	

The structured data is worse than the page
Marketplace pages publish machine-readable product data as schema.org JSON-LD. I checked what it contains.


Field
	What it should say
	What it actually says
	Offer type
	AggregateOffer with lowPrice and highPrice for a variant range
	Plain Offer with a single price
	Price
	The price of the configuration requested
	9.89, the cheapest variant. It does not update the price upon clicking a more expensive variant
	aggregateRating
	The product's rating, shown on the page as 5.0 from 5.2k ratings
	The seller's rating, 4.96 from 198,853 ratings
	

  



Why this matter? An agent that trusts structured data over the rendered page, which most extraction pipelines do, receives a confident wrong answer with no ambiguity marker. The price is a valid lower bound but is published as a point value.
The same failure in a deployed product
I asked a live AI shopping assistant for the cheapest 9.5 litre carton. It returned a ranked comparison naming one seller as 27 per cent cheaper, supported by a computed cost per litre. The seller was in fact more expensive for the size requested. The output carried no uncertainty marker.

3. Why current agent architectures make this likely
Web agents do not read a page the way a person does. openJiuwen's published architecture reads the control tree, meaning the DOM plus the accessibility tree, by default, and only adds screenshots when the page is judged ambiguous.


  



This matters for the failure above. On a multi-variant listing the DOM and the screenshot agree with each other, because both show one price and four size buttons. There is no conflict for an ambiguity check to detect. The information is missing rather than contradicted, so adding vision does not help.


I cloned openJiuwen's agent-core and read the browser agent's system prompt. The retrieval policy is explicit and it is minimising.


Instruction in the prompt
	Effect on gated pages
	Avoid unnecessary page snapshots
	Fewer observations per page
	Choose the smallest compact probe that matches the task
	Card-level extraction preferred
	On product and marketplace pages call browser_probe_cards before broad extraction
	Captures title, price, rating, availability from the card
	If the card probe returns the fields needed, use that as evidence for final reporting instead of extra DOM scans
	Stops before opening variants
	Never dump the entire document body
	No exhaustive fallback

6. Method sketch for RQ3
The right method depends on what kind of answer the question needs.

Prof Notes
* Can look at whether user’s review is useful or not (rlly positive or negative) 
* Shipping cost / Discount after combination (make clear of what is in-scope and out-scope): limitations


Question type
	Example
	Method
	Guarantee
	Exact
	Which variant is cheapest
	Branch and bound using the published "from" price as a lower bound to skip whole listings
	Exact, when bounds exist
	Distributional
	Do buyers mention leaking
	Stratified retrieval, for example filtering to one-star reviews, plus a sequential stopping rule
	Bounded error rate
	Point lookup
	In stock in size M
	Single targeted retrieval
	Exact
	Unresolvable within budget
	Any of the above when retrieval fails
	Report what is missing, or use ask_user
	No false confidence
	

Evaluation. Interactions spent against answer correctness, plotted against two baselines. Exhaustive retrieval is correct and expensive. Unmodified openJiuwen is cheap and sometimes wrong. The gap between them is the result.
