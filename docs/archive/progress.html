A new rule that catches nearly everything, including my own right answers

All my existing rules read something the answer says about itself, so an agent that says less gets checked less. The new rule reads the question and the record instead.

The principle: naming the best item in a market is only supported if the evidence rules out the rest of the market. The market generator already works out the fewest shops any correct method could open, after skipping everything the advertised prices allow. For these markets that is 11 of 15.
The same 125 plain-agent runs, replayed free because the check never opens a page

It also refuses four answers my own method got right. Those four opened nine shops where the sound minimum is eleven, so my method skips more than its own reasoning justifies and got away with it on these draws. Under the new rule my method reads 7 right, 5 refused, 0 wrong instead of 11 right, 1 refused, 0 wrong. I report both, because the runs happened under the old rules. This is the clearest case in the project of an answer being right without being earned, and a rule found it rather than a score.

My own shop was giving the answer away

Magento writes the extra cost into the size menu, so it reads 2 x 9.5L +$32.50 before you click anything. The thing I am studying was readable without interacting. I added a version of the page that hides it, switched on by the browser the agent uses, so ordinary browsing and every run already recorded are untouched.

Label arithmetic re-counted on 7 October from the run logs: a base price plus a surcharge is added up in the reasoning of 9 of these 12 runs, and in none of the final answers. The 4 of 12 first reported here could not be reproduced.

The agent starts clicking, from never to two runs in three, where across 122 earlier runs it had chosen a size twice in total. It works 64 per cent harder and is no more right. In both versions every right answer opened 12 to 15 shops and every wrong answer opened exactly 4. So the wall that decides the answer is between the search page and the shops, not inside a shop.

A second agent, and my prediction was wrong

Everything so far came from one agent, whose shortcut reads the visible window and reports four shops where there are fifteen. So I wrote a plain browsing loop with no shortcut at all, expecting it to look at more.

Twelve runs each, same questions, same model, same market
AgentRightShops openedActionsCost/run
The shipped agent3 of 126.510.2$0.137

It looks at fewer shops, not more, for twice the work and six times the money. It spends its actions re-searching, sorting by price, sorting by name and rephrasing the query. So the four-shop ceiling is not what makes the AI stop early.

And where the difference sits is the interesting part

Its right answers came from opening 2, 2, 3 and 3 shops, so looking more does not predict being right for this agent, and it should not. The question it answers well is the one a single counterexample settles. How much looking an answer needs belongs to the question, not to the agent, which is exactly what my method encodes. That is the thesis of the project turning up in its own control.

5How much looking is enough is a property of the questionShown twice this week, by the new rule needing a different floor per question, and by the second agent doing well on exactly the question that needs least looking

6. What I got wrong this week

Four, all in my own tools rather than in the agent, and all caught before they reached a number in a document. That is the pattern for this project and it is why I now treat a new measurement as suspect until a deliberately wrong input makes it complain.

Caught, and what each would have done
WhatWhat it would have produced
My first attempt at hiding prices did not workIt hid them on the search page and not on the shop pages, so half of each run saw one version and half saw the other. Cost $2.72 and is kept, marked as not interpretable, rather than deleted
The replay matched questions by nameThe two markets ask the same questions on purpose, so unseen-market runs would have been marked against the first market's answers

THE HONEST LIMIT

Twelve runs is a direction

Enough to see a difference this size, not enough to put a confidence interval on it. The budget buys breadth or depth and I have chosen breadth, on the grounds that one more market changes the story more than three more repeats would.

THE RULE I KEEP

Freeze before building

A rule written after seeing a market's failures cannot be tested on that market. The new rule is frozen and the clothing market that will test it does not exist yet.
