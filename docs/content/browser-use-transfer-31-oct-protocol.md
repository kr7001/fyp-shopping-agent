# Browser Use transfer study, 31 October 2026

Status: design specified before adapter testing; paid pilot not approved; scored study not launched. This is a separate exploratory portability experiment. The earlier block, markets, human verdicts and analyses remain frozen. Changes to this dated design must be recorded before scored execution.

## Question and interpretation

Can the unchanged model-parsing retrieval block operate in front of Browser Use, and does its assistance improve final-answer correctness on a fixed previously studied market? This tests one second framework under one language model. It cannot establish universal model/agent independence. Browser Use native observation/tool behaviour differs from openJiuwen; compare the two Browser Use conditions internally, never pool their results with historical arms. Without a new exhaustive condition, make no claim of savings against exhaustive browsing on this framework.

## Scored design

- Quenby fixture: env/fixtures/tee_replication_28_oct.json. This is a known fixed-market transfer test, not another unseen-market replication.
- Questions: the seven reading_independent task IDs from experiments/tasks/claim2_replication_28_oct.json plus tee-headline. Keep their exact frozen query wording. This excludes clarification and decline coverage from the portability claim.
- Conditions: Browser Use with a common background briefing; the same Browser Use configuration plus the unchanged model-parser block. Both receive exactly primitives.LABEL_NOTE before the task. The block's frozen plan may repeat that warning; record the final text and acknowledge the assistance package differs beyond the stopping rule.
- Eight questions, two conditions, two repeats: 32 scheduled slots. Interleave arms within each question and reverse their order in round two. Use the canonical task list, no selection from outcomes.
- Executor and parser: deepseek/deepseek-v4-flash, with the recorded provider route from the Quenby protocol. Executor temperature 0.2, parser temperature 0. Parser prompt, normalisation, fallback, planner and block files remain unchanged. Any transport-level token caps or provider price ceilings are recorded as new execution conditions.
- Browser Use 0.13.14, Playwright 1.63.0, local Chrome with its actual build recorded; text-only, no cloud browser, model switching, telemetry or default extensions. All browser/helper/parser model requests use the guarded transport and recorded routing.
- Fresh profile per trial; gated user agent; 1280x720 viewport; local-shop network restriction and service-worker blocking. Do not describe navigation-domain allowlists alone as network isolation. Native Browser Use navigation, click/input, dropdown selection, tab, extraction and JavaScript-evaluation actions remain available. The upload_file tool is disabled to prevent local-file attachment access, and the screenshot action is disabled for this text-only condition. Managed read/write actions remain confined to the agent scratch workspace. This broader action surface is part of the new framework condition; network confinement does not prevent inspection of hidden DOM data or same-origin resources.
- Candidate URLs and advertised prices come only from observed rendered result pages. No fixture, task expect field or answer mapping is available to the planning/execution call. The scheduler may read task definitions; emit stripped runtime input files.
- Native step cap, wall-clock limit, maximum output tokens and request byte limits are fixed in the launch configuration before execution. They need not equal openJiuwen tool-call counts, which are not comparable units.

## Development and pilot

First run scripted/no-network-LLM checks on a local synthetic shop. These must demonstrate complete two-page listing reads, selecting a variant then waiting for its price, successful product-page counting (including tabs and batches), rejecting missing/soft-404 pages, and confinement of off-origin requests. Check transport serialization and cost accounting with synthetic OpenRouter responses and failures.

Next prepare a four-slot paid pilot: two predefined questions (a cheapest-buyable task and a count-buyable task), each in both conditions, on the existing Thurlby development market (env/fixtures/tee_dev.json, 45 products) if its current live fixture is verified. Pilot outputs are development evidence only and never enter the 32 scored results. If unavailable, prepare a separate declared development fixture; do not quietly substitute Quenby. The model parser's own call is charged. Pilot approval requires exact command/config/code, estimate, cap and an independent verifier receipt. Proposed pilot cap is USD2, preserving at least USD20 of account credit. This is a proposed ceiling, not permission or a measured estimate. No main-study price or completion-time promise until the pilot is measured.

## Measurements and exclusions

Preserve every scheduled slot and failure. Two repeats do not supply eight or sixteen independent questions. Final committed answer correctness is scored blind by the student with the existing reading rules; retain human and automatic scores separately. Unscorable text remains unscorable under the stated rule; an execution that produces no answer is a failure, not a technical exclusion by convenience. An unreadable export is repaired from original text before scoring, without changing the answer. Unexpected block closure is recorded as failure for the intended answer task, not silently replaced by a rules-only run.

Count unique candidate product URLs actually reached successfully, using response plus product-page evidence rather than URL shape or the agent's own count. Include new tabs and intermediate actions; validate the counter on a known scripted trace. Record hidden-price/source access separately where observable. Sum provider-reported charges per request across browser, extraction and parser calls. Missing charge is unknown, never zero; stop further paid calls until reconciled. Record input/output tokens, provider, latency, response IDs and failures. Browser infrastructure cost is not measured.

Report per-question paired outcomes, totals, listings and charges descriptively, with both rounds visible. No significance threshold is a success criterion; do not add repeats to pursue a favourable p-value. Analyse this study separately from Wexcombe, Quenby/openJiuwen and the still-blinded matched-briefing study. Keep the baseline and block outputs blinded until the student's CSV is complete and validated.

## Spending and operational stops

A paid command must bind code, package lock, protocol, input and configuration hashes and pass independent verification. Existing credentials are not approval. Enforce a per-request reservation derived from capped input/output and provider price limits, a cumulative cap, a USD20 account reserve, and an absolute Singapore-time deadline. Account snapshots can lag or decrease; neither event resets cumulative spend. All retries/helpers are included. Fail closed on missing cost, unknown request shape, account read failure, unexpected provider, violated hashes or deadline. Keep the laptop awake and terminate only processes owned by this launcher. Chrome is installed separately; record its actual version for every trial and compare it with the preflight version, since an automatic browser update is a condition change. Record interrupted work without silent automatic replay. Re-approval and a new verified command are required to resume beyond the declared command.
