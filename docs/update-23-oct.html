Part C. Fixed today, before any money was spent

The verifier refused the pilot twice before passing it: first on two blockers, then on one cost estimate that was too low. Each refusal was worth having.

  1. The simulated shopper could contradict the question. When the block asks back "do you mean listed, or in stock?", our script always answered "listed". For "How many listings can sell me a size M today?" that is the opposite of what the question says, and the run was then marked against the other answer. Now the script answers with what the question itself means, like a real shopper would. Every ask is still counted, so an unnecessary ask still shows.
  2. The block's word list asks back even when the wording already settles it, and the model reading the question can't overrule the list. This is a design flaw, not a test bug. It is decision 10 in Part E. With fix 1 it costs one extra exchange, not a wrong answer.
  3. The $8 limit could be overshot. The old check looked only at what was already spent, and one Haiku run can cost $1.40. Now each step starts only if what's spent plus that step's worst case stays under $8, and the run stops if the account can't be read.
  4. DeepSeek's replies might not have been readable. If DeepSeek puts its reasoning before the answer, or sends its reply in pieces, our reader would fail or crash. Now it finds the answer, or falls back to the rules and records that it did.
